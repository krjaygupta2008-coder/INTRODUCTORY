Foundation

Core Concepts

Understanding these concepts makes everything else click instantly.

Repository (Repo)

A project folder tracked by Git. Contains all files, history, and configuration.

  • Local repo on your machine
  • Remote repo on GitHub/GitLab
  • Contains .git/ hidden folder

The Three States

Every Git file lives in one of three states. Understanding this is crucial.

  • Modified — Changed but not staged
  • Staged — Marked for next commit
  • Committed — Safely stored in history

Branching

Branches are independent lines of development. Keep main clean, work on features separately.

  • main or master — production
  • feature/* — new features
  • hotfix/* — urgent fixes

Commit

A snapshot of your project at a point in time. Think of it as a "save point" with a message.

  • Has a unique SHA hash ID
  • Contains author, date, message
  • Write meaningful messages!

Remote vs Local

Local is your machine. Remote is the shared server (GitHub). Sync between them with push/pull.

  • origin = default remote name
  • push sends your changes up
  • pull fetches and merges

.gitignore

A file telling Git what NOT to track. Essential for security and cleanliness.

  • node_modules/
  • .env files with secrets
  • Build outputs, logs, temp files

Clarification

Git vs GitHub

They're related but not the same. Here's the difference.

Aspect Git GitHub
What it is A distributed version control system (software) A web-based hosting service for Git repositories
Function Tracks code changes locally on your machine Hosts repositories online for collaboration
Requires internet No — works entirely offline Yes — it's a web platform
Created by Linus Torvalds (2005) GitHub, Inc. — now owned by Microsoft
Alternatives SVN, Mercurial, Perforce GitLab, Bitbucket, Gitea, Codeberg
Pro Knowledge

20 Remarkable Points

Tips, gotchas, and wisdom that separate beginners from pros.

01

Commit Early, Commit Often

Small, frequent commits are better than giant ones. They're easier to review, revert, and understand in history.

02

Write Imperative Commit Messages

Use "Add feature" not "Added feature" or "Adding feature." A commit message should complete this sentence: "If applied, this commit will ___"

03

Never Commit Secrets

Once a secret (API key, password) is committed, it's in history forever. Use .gitignore and tools like GitGuardian.

04

Use Branches for Everything

Never commit directly to main in team projects. Create a branch, make a PR, get it reviewed, then merge.

05

Pull Before You Push

Always git pull before git push to avoid merge conflicts and rejected pushes.

06

Reflog is Your Time Machine

Even after a bad reset, git reflog keeps a record. You can recover almost anything for about 90 days.

07

.gitignore Before First Commit

Set up your .gitignore before committing. Removing tracked files later is a headache.

08

SSH Keys > HTTPS Passwords

Set up SSH keys for GitHub. No more typing passwords, and it's more secure. Generate with ssh-keygen.

09

Stash Before Switching

Got uncommitted changes and need to switch branches? git stash saves them temporarily without a commit.

10

Atomic Commits

One commit = one logical change. Don't mix bug fixes with feature additions in the same commit.

11

Rebase for Clean History

Use git rebase to linearize history before merging. It makes the log much easier to read.

12

Use Meaningful Branch Names

Name branches descriptively: feature/user-authentication, bugfix/login-error, hotfix/security-patch.

13

Review with git diff

Always run git diff before committing. You'll catch debugging code, typos, and accidental changes.

14

GitHub Issues = Project Management

Use GitHub Issues to track bugs, features, and tasks. Link them in PRs with "Fixes #123" to auto-close.

15

Protect Your Main Branch

On GitHub, enable branch protection rules: require PR reviews, status checks, and prevent force pushes.

16

GitHub Actions for CI/CD

Automate testing, building, and deployment with GitHub Actions workflows defined in .github/workflows/.

17

README is Your Landing Page

A good README includes: what, why, how to install, how to use, and how to contribute. It's your project's first impression.

18

Fork for Open Source

To contribute to projects you don't own: Fork → Clone → Branch → Commit → Push → Pull Request.

19

Git is Distributed

Every clone is a full backup. If GitHub goes down, anyone with the repo has the complete history.

20

Learn vim basics (or set default editor)

Git opens vim by default for interactive operations. Learn :q! or set your preferred editor with git config core.editor.
